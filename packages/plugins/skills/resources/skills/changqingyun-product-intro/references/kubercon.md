# KuberCon 常青容器云平台

依据：产品介绍 2026-V1.8，以及可观测性链路追踪分享稿。这是容器平台介绍，不是 ANI，也不是开物。

## 定位

面向大型企业复杂 IT 环境的 Kubernetes 容器管理平台。材料中的两句话：

- 在 Kubernetes 之上构建企业级分布式多租户容器平台。
- 一个平台里统一 DevOps、服务网格、应用生命周期、多租户、多云多集群、存储与网络、可观测与安全，避免多套工具拼装。

两个听众：基础架构团队要基础设施即代码和集群管控；业务开发团队要从代码提交到应用上线的自助交付。材料中的交付口径是「分钟级业务交付」，这是产品介绍用语，现场工期以方案为准。

## 可讲能力

- 多租户：企业空间（Workspace）/ 项目（Project）/ Namespace 三级隔离；平台、企业空间、项目三级角色；可对接 SSO、LDAP、AD；有审计、许可证和配额。
- 可插拔：材料写最小安装 2C4G；生产按需打开 DevOps、服务网格、日志、告警、计量、多集群、边缘，支持集群级开关和独立升级。2C4G 是最小安装说法，不说成生产推荐配置。
- 多云多集群与边缘：统一控制台管理自建、托管和边缘节点上的应用分发、灾备和可观测。具体隧道和联邦组件名只在客户追问架构时再提，不作为开场必背。
- 异构与信创：x86 与 ARM（鲲鹏、飞腾），材料还写到海光；操作系统提到银河麒麟、统信 UOS、EulerOS、凝思。一云多芯是「统一管理界面管理不同芯片集群」，不要说成任意芯片无需适配。
- 网络与存储：安装器集成 Calico、Flannel 等 CNI，以及 NFS、Ceph RBD、GlusterFS、商业存储 CSI 等；动态适配 CSI 的克隆、快照、扩容和 RWO/ROX/RWX。现场以兼容清单为准。
- 弹性伸缩：按并发、响应时间等业务指标扩缩，材料把传统集成方式的 2–3 天对比为秒级自动扩缩。这是介绍稿对比，不保证客户现网同样数字。
- DevOps：独立 DevOps 工程、多集群凭证、Jenkinsfile 或图形编排、SonarQube、发布到 Kubernetes；代码源包含 GitHub、GitLab、Git、SVN、Bitbucket。S2I/B2I：不写 Dockerfile，从源码构建镜像。流水线全家桶材料写到 Jenkins、Argo CD/Flux CD。
- 应用商店：上传、测试、部署、发布；默认有内置应用，也可用模板追加。
- 可观测：指标、日志、链路。链路追踪材料使用 DeepFlow，eBPF 零侵入加 OpenTelemetry；Trace/Span；页面从概览、服务清单、拓扑、应用到分布式追踪、Pod、协议下钻。培训稿示例是一次请求从约 200ms 慢到约 2s，用链路定位到慢的 Span。不要把示例耗时说成客户现网指标。培训稿里的测试地址和账号禁止对客户复述，也禁止写入方案。

控制面材料中的产品名是 kubercon-apiserver、kubercon-ui。不要改口叫上游 KubeSphere 的 ks-console，也不要把上游开源命令当成常青云界面名称。

## 案例（只讲材料标题和已写收益，不添数字）

- 中国电信中山分公司业务云平台：利旧异构设备、统一纳管、缩短交付、业务迁移。材料同时提到接管 VMware 与 V2V。页内另有客户名列表，未逐条写成果的，不要展开成案例故事。
- 中国国家版本馆云平台：同城双活、等保三级、图形化运维、材料写云平台 2 小时内部署和数据 3 副本。这些是该案例表述，不套到其他项目。
- 金电集团（央行软开中心）信创桌面云：集中管理、数据集中、全栈信创、远程访问。桌面云是常青云产品线能力，不要说成 KuberCon 容器平台本身就是桌面云。
- 黄埔区信创云：扩容、一云多芯、计量计费与云市场派发。

未在材料中写出的客户、金额和性能百分比，一律不编。

## 和另外两款的边界

KuberCon 管云原生应用和 Kubernetes 平台。模型仓库、训练微调、推理密钥和 GPU 账本讲 ANI。员工岗位、资料库和办公文件交付讲开物。装机命令和巡检步骤交给「常青云容器运维顾问」，本顾问不输出可执行安装命令。
