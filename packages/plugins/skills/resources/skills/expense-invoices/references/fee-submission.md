# 费用报销：电子提交与纸质打印

纸质材料及 OA 字段以使用者所在单位的要求为准。OA 查找和 PDF 导出参见[导出流程](oa-export.md)。

## 先明确两种材料用途

| 材料 | OA电子提交/核对 | 最终纸质提交 |
| --- | --- | --- |
| 本批费用申请单（OA可能名为费用报销单） | 实际填写、提交并审批 | 打印已核对的当前完整系统PDF；用户明确未审批完也可以打印，审批状态另记 |
| 餐饮、业务消费、酒水及其他需付款凭证的非网约车费用项 | 上传付款截图到对应费用项的报销栏/明细行附件，招待费与该项原发票一一对应 | 付款截图不打印 |
| 普通出租车票 | 原票及付款截图匹配费用项，截图只作电子附件 | 打印原出租车票，付款截图不打印 |
| 网约车发票 | 上传对应明细行 | 计入发票清单并打印 |
| 网约车完整行程单 | 同对应发票上传，保留原件全部页 | 不打印，留原始文档 |

最终费用纸质材料只有“费用申请单、相关发票”两类，另按规则准备专票及通行发票的额外独立加印件。付款截图不打印。不能把OA附件清单直接复制成纸质清单；本表不决定差旅材料组成。

## 整理和填写

进入OA前先按[脚本与批量填报](automation.md)生成本地候选清单并处理机械缺口；该参考也定义按行批量录入、一次选择多附件和保存后集中比对方式。它不改变本页的材料和最终发送分工。

1. 先匹配每个消费项目的原票、付款记录和用途。费用项数按实际消费项目确定，不固定六项；一项可含多张匹配原票，多日市内网约车可按用户确认合并一项，摘要注明实际期间。
2. 进入OA首页→我的流程→费用报销单，核对实际申请人、公司、部门及日期。普通公司费用按页面要求选择“公司费用”；项目编码、人员和公司以当前页面为准，不套用上次示例。
3. 核对费用承担部门、收款信息、付款类型、往来单位、开户银行及账号，银行名称与账号分别填。密码和完整账号不记录到通用流程或截图中。
4. 按实际情况填写是否用车、是否借支冲账等字段。发票张数按真实原票数，不按费用项数、附件数或打印页数算；缺原票不能因已有付款截图就算成已核发票。
5. 用“新建”逐项填日期、分类、摘要、金额、发票类型、税额和备注。日期按付款时间，不能用开票日代替；付款时间缺证据就保留待核。业务消费与酒水归业务招待费，成都市内用车和出租车票归交通费，实际OA科目名从页面核对。
6. 发票类型及税额按页面说明填写：已观察普通发票税额0，专用发票/通行费发票按票面税额；其他情形核对当前说明。金额修改后检查自动合计和大写，保持票面、实付及拟报金额各自的含义。
7. 对应明细行上传原票；招待费同时将付款截图上传到对应费用项的报销栏/明细行附件，不以仅存本地或顶部汇总附件代替。其他需付款凭证的费用项也只上传电子截图；网约车同时上传完整行程单，不要求付款截图。按页面附件名及内容确认截图和发票属于本项，核对金额、日期、商户及附件是否实际保存，配套凭证不重复加金额。找不到对应行入口时先记录，不能编造按钮或称已上传完成。

## 提交、审批和打印

- “保存待发”只证明草稿保存；“发送”才发起电子提交。后续由Codex完成填写、上传附件和核对，最终发送由用户本人操作；凭真实成功提示或本批单据状态确认已发送。
- 取得同一申请的当前完整原系统PDF，核对编号、人员、金额及全部页。用户明确未审批完也可打印，无需等待或要求重下载审批后版本；流程批准和公司付款分别记录，当前打印版不证明审批完成。
- 将已核对的当前完整申请单和发票清单放入本批费用报销目录，付款截图及行程单留原始文档/电子提交附件，不打印；网约车发票仍纳入发票清单。
- 发票每面可排两张，允许双面打印；专票及通行发票每张需额外单独加印一张，不与其他票拼版。加印不增加发票张数或报销金额；长票/多页票仍保留全部页。纸质材料贴左上角。实际排版细节见SKILL.md“打印格式与文件保护”。
- 检查所有页完整、金额日期商户可读、截图/票据对应及无重复打印。未取得本批申请单或仍缺出租车票，交付已整理文件并明确缺件；不创建占位单据，也不称纸质材料已齐或费用已报销。

内部阶段建议分别记录：材料整理中、待电子提交、已发送待审批、审批完成待补完整单据、纸质材料齐备、已交纸质、公司已付款。仅推进有证据的阶段，不因改好技能就推进实际OA状态。
