# 脚本与批量填报

## 分工

脚本负责本地文件存在性、SHA256、Decimal金额加总、附件关联和PDF机械拼版。票面/截图内容、用途、归属、退款与折扣的解释仍需核实。脚本通过不等于税务查验、OA上传成功或审批完成。

先复用当前批次处理记录，不另建长期台账。生成的候选清单和拼版索引放`原始文档/内部核验/`，最终打印目录仍只有申请单、发票等规定材料。输出必须为新路径；替换最终文件前备份旧生成件，原件只读。

## 批次预检

标准库Python即可，无需安装依赖：

```sh
python3 scripts/prepare_oa_plan.py '/批次/原始文档/处理记录.json' --output '/批次/原始文档/内部核验/OA填报候选_新版本.json'
```

默认检查`费用报销`；可用`--category 差旅报销`生成差旅候选，但其申请关联及结账单不由脚本判齐。输出只包含选中类别，配套截图/行程单不计发票金额。退出码0表示无机械缺口可供复核，2表示有待处理项；异常输入停止，不改源记录。

沿用现有`records`中`document_type=invoice`记录：票号、类别、原票路径及hash、币种、票面额、`proposed_reimbursement_amount`、`payment_date`或`expense_date`、科目、`oa_summary`、付款截图路径/hash。网约车按`matched_invoice_id`寻找全部行程单记录，优先电子附件路径。相对文件路径以批次目录为基准。

结构化确认的OA专用值可写在该原票记录的`oa_fields`：

```json
{"oa_fields":{"date":"2026-10-29","amount":"80.00","subject":"销售费用_交通费","summary":"打车费用（示例）","tax":"0.00"}}
```

这只是字段格式示例，不自动应用到别的票。值必须已有本批证据或用户确认；记录确认出处。旧记录缺拟报金额时，仅用票面计算`candidate_total`并标记不能直接填报；缺日期不得以开票日补齐。普通票默认OA税额0，其他票种未填税额即提示核对。脚本一票一行，不自动合并/分摊；跨批去重另按明确历史范围核票号及hash，不能把批内预检当作跨批验收。

## PDF拼版

需`pypdf`，使用本机已有相应依赖的Python；不要为此修改系统Python。纯PDF清单示例：

```json
{"invoices":[
  {"invoice_id":"已核票号","file":"/原票.pdf","sha256":"已核hash","verified":true,"extra_copy":false},
  {"invoice_id":"另一已核票号","file":"/住宿专票.pdf","verified":true,"extra_copy":true,"full_page":true}
]}
```

```sh
python scripts/compose_invoice_pdf.py '/内部核验/拼版输入.json' --output '/内部核验/拼版候选_新版本'
```

按输入顺序拼版：单页PDF上下两票、保持比例；多页票全部原页连续保留，长票可明确`full_page:true`独立保留。`extra_copy`必须逐票明确，专票/通行票为true；额外件每票独立文件、全部原页、不与别票拼版。原票不修改，不自动识别票种。重复票号/文件hash、未核票、已存在输出目录会拒绝；候选PDF及JSON均留内部核验，核实全部页可读后才替换最终清单。不会自动替换现有打印PDF，也不生成截图打印文件。

## OA减少往返

1. 先核对本批抬头字段：公司、申请部门、费用承担部门、收款银行及账号来源。两个部门分别核对；不能照抄默认旧组织，也不能把“工资卡”理解成某银行选项。本批确认值放处理记录，不将某个部门或银行硬编码为默认值。完整账号不进入候选清单、日志或证据截图。
2. 准备一次完整的候选行数据，明确日期、科目、费用说明、实付拟报额、发票类型、税额及附件路径。用户已确认折扣差异并按实付申报时沿用确认，不重复追问同一差异。客户招待费摘要以用户本批指令为准，其他费用不自动全改招待。
3. 观察当前页面后建立按行的稳定定位器，先完成一行验证再批量处理同构字段。避免对每个输入都请求完整页面；一行或一小组确定性操作后读取必要字段。不得绕过当前浏览器工具的观察/权限要求，或用任意脚本、隐藏接口直接改OA状态。
4. 每行附件可一次选择原票及配套截图/完整行程单，等待上传结束，读取该行附件名与数量。附件名与文件内容一起核对，不能仅按总数判断。上传权限不足只处理具体阻塞；用户已启用后先重试一行，避免重传全部。
5. 保存前集中比对抬头、行数、日期、科目、摘要、金额、税额、原票数、各行附件和总计。每行内容相符才点保存待发；保存后等页面稳定，再读取同一草稿关键字段及逐行附件。一次短暂页面超时不等于保存失败，先核对当前页/草稿身份，避免重复创建或上传。
6. 只在发现新差异时重新检查受影响项。保存待发与发送分开；最终发送由用户。截图避开完整银行账号，留下可核实的保存结果。

本参考优化执行方式，不授予新OA/邮箱权限，不重跑已通过且来源hash未变的材料，也不推进真实报销状态。

## 草稿恢复与差异对照

- 卡住时接续用户打开的页面；有“恢复未保存数据”先核对单据身份，再恢复并读取现有字段和附件。先对照现状，只补差异。附件权限或保存超时先核对同一草稿实际结果，再决定是否重试。
- 差旅先取得对应出差申请，按申请、费用明细、逐行附件三组核对。住宿日期、合并打车日期、票种税额按本批已确认口径。个人购买的铁路票按实际行程逐张登记。纸质出租车票经用户确认后计入原票张数，电子附件可为付款凭证，另记纸票待贴。酒店订单截图用于核对住宿，按票面及付款证据确认发票和报销金额。
- 晚到票据先匹配原行或确认新增行，重新核对受影响的合计、原票张数、对应附件和打印页。新增原票才增加原票张数，住宿专票加印件不增加张数。打印交付明确每张专票在常规清单内已有一份，另用对应独立文件加印一份。

用 `python3 scripts/compare_oa_snapshot.py 确认值.json 页面读取值.json` 对照两份本地 JSON。先核对同一单据身份，再独立从当前 OA 界面提取实际值。两份都提供下列字段，按 OA 行序排列。无附件用空列表，附件项填实际上传文件名。账号只记录四位尾号。银行文本统一用同一格式。完整字段示例如下：

```json
{
  "application_department": "已确认部门",
  "cost_bearing_department": "已确认部门",
  "bank": "已确认银行选项及名称",
  "account_suffix": "0000",
  "invoice_count": 1,
  "total": "35.00",
  "application_attachments": ["出差申请.pdf"],
  "rows": [
    {"date": "2026-11-03", "subject": "销售费用_差旅费", "summary": "客户拜访出租车费", "amount": "35.00", "invoice_type": "其他", "tax": "0.00", "attachments": ["付款凭证.jpg"]}
  ]
}
```

脚本校验每行及单据合计，附件顺序可不同，缺项、串行或重复附件会报差异。退出码 0 表示给定字段一致，2 表示差异或输入无效。它不读取 OA、不自动确认票据真实性，也不以张数等于行数为假设。
